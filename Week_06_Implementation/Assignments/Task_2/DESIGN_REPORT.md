# Repository Chunking Design

The script indexes Python source and tests plus relevant text and configuration files as JSONL records, leaving the cloned repository unchanged. Python files use AST-aware chunks; other included files use line-based chunks. Each record includes the relative path, line range, symbol or document label, estimated token count, and source text.

Included types are `.py`; documentation (`.md`, `.markdown`, `.rst`, `.adoc`, `.txt`); and text configuration/data formats (`.toml`, `.yaml`, `.yml`, `.json`, `.ini`, `.cfg`, `.conf`, `.properties`, `.xml`, `.css`, `.html`, `.csv`). Common extensionless project files such as `README`, `LICENSE`, `Dockerfile`, `Makefile`, and `.gitignore` are also included. Environment files are limited to the explicit template names `.env.example`, `.env.sample`, and `.env.template`; other `.env.*` files are excluded to avoid indexing secrets. Binary or non-UTF-8 files are skipped, as are generated/cache/vendor directories, generated/minified source files, and common dependency lockfiles.

Chunks target about 550 estimated tokens, with a 700-token limit for oversized units. The estimate counts word and punctuation groups, so it is a lightweight sizing heuristic rather than a model tokenizer. Python AST boundaries keep definitions together; oversized classes are divided at member boundaries, and unusually large units fall back to line-based splitting. Non-Python text is grouped by source lines, splitting unusually long lines when needed. This balances coherent retrieval context with manageable chunk sizes without external dependencies.
